# Changelog

## 2026.11.4

Same Base UI release and commit as 2026.11.3.

### Changes that you must make

These rules hold for the popup and the backdrop of Dialog, Alert Dialog, Popover, Menu, Context Menu, Menubar, Tooltip, Date Picker, Date Range Picker and Time Picker:

- Remove `appear` from a `<Transition>` around a popup or a backdrop. The element shows one update after its mount, so the enter runs with no `appear`. With `appear` and JavaScript hooks, a virtual DOM app calls `before-enter`, `enter` and `after-enter` two times. The demos of these families have no `appear`. ([#847](https://github.com/vase-ui/vase-ui/pull/847), [#848](https://github.com/vase-ui/vase-ui/pull/848))
- The content of a popup unmounts at the end of its leave, not at the close. ([#847](https://github.com/vase-ui/vase-ui/pull/847))
- A JavaScript `enter` hook that starts from fixed keyframes, such as `opacity: [0, 1]`, jumps at an open during the leave. Give the closed style in the style sheet, and animate from the current style. ([#847](https://github.com/vase-ui/vase-ui/pull/847))
- After a close, the `payload` of the default slot of the root is the payload of the last render while the root was open. So the popup that leaves keeps its content when the parent clears the trigger. ([#847](https://github.com/vase-ui/vase-ui/pull/847))
- A popup or a backdrop that leaves has `inert` and no `hidden`. A closed part with `keepMounted` has `hidden` and `inert`. ([#847](https://github.com/vase-ui/vase-ui/pull/847))

### Changed

- The popup and the backdrop of the families above render their content from the update after their mount. So each item of a `v-for` in a popup renders one time at an open, not two times. ([#849](https://github.com/vase-ui/vase-ui/pull/849))

### Fixed

- In the families above, an open during the leave of a popup keeps the same popup and backdrop, and a CSS transition goes back from where it is. The popup does not fade out and fade in again. An open by another trigger moves the same popup to that trigger, with the payload of that trigger. ([#847](https://github.com/vase-ui/vase-ui/pull/847))
- A popup takes the focus at each open, also after a close and an open in one task. A close that moves no focus, such as with `finalFocus` false, takes the focus out of the popup that leaves. ([#847](https://github.com/vase-ui/vase-ui/pull/847))
- The viewport of Popover, Menu and Tooltip measures the popup when it shows. So a positioner that takes the size variables has the size of the popup at the first open. ([#847](https://github.com/vase-ui/vase-ui/pull/847))
- Menu: the `element` slot of `Menu.Popup` renders while a submenu leaves. A parent menu leaves at its close after its submenu unmounted during its leave. ([#847](https://github.com/vase-ui/vase-ui/pull/847), [#849](https://github.com/vase-ui/vase-ui/pull/849))
- Tooltip, Popover, Preview Card, Navigation Menu and Menu: a pointer that leaves the trigger away from the popup closes it after `closeDelay` only. The safe triangle to the popup starts at the last point of the pointer on the trigger. ([#844](https://github.com/vase-ui/vase-ui/pull/844))
- At the first open, a positioner with a CSS transition of its place shows at its place. It does not move in from the top left of the page, and it needs no `[data-instant]` rule. A popup that flips at its first place enters from its final side. ([#849](https://github.com/vase-ui/vase-ui/pull/849))
- A popup takes its first focus after the update of its open, when the attributes of its children are final. So a busy Alert Dialog gives the focus to a Cancel button that becomes focusable at its mount. ([#850](https://github.com/vase-ui/vase-ui/pull/850))
- Combobox: a form reset gives the text the label of the value that holds after the reset. When the parent controls the value and keeps it, the text is the label of that value. For the text, the reset emits only `update:inputValue`, and no change event. ([#850](https://github.com/vase-ui/vase-ui/pull/850))

## 2026.11.3

Same Base UI release and commit as 2026.11.2.

### Changed

- Menu, Select and Combobox check the visibility of the items only up to the item that they need: at an open, a filter, a key, a release, a pointer move and a scroll arrow. A long list does less work, and the result does not change. ([#834](https://github.com/vase-ui/vase-ui/pull/834))

### Fixed

- Drawer: each popup has `--drawer-frontmost-height` while the frontmost drawer has a height, and the frontmost drawer gives its own height. So with the CSS of the Drawer page, the frontmost drawer of a stack and a single drawer follow a swipe. A popup has `--drawer-height` only while it has a height, so a drawer below a nested drawer keeps its height at the open and the close of the nested drawer. ([#837](https://github.com/vase-ui/vase-ui/pull/837))
- The README, the package description and the parity page give 37 Base UI components: one for each component page of the Base UI docs. Base UI shows the parts of Radio on its Radio Group page. ([#836](https://github.com/vase-ui/vase-ui/pull/836))

## 2026.11.2

Same Base UI release and commit as 2026.11.0: Base UI 1.9.0, with later Base UI changes through `315eba7a` (2026-11-13).

The rules below hold for each family. The family list after them gives only what the rules do not say.

### Changes that you must make

#### Rules for each family

- Vue: the peer range of `vue` is `^3.5.46 || ^3.6.0-0`. On Vue 3.5, use 3.5.46 or later. ([#762](https://github.com/vase-ui/vase-ui/pull/762))
- Components: import each part from its namespace, such as `Dialog.Root`, or as the component of a family with one part, such as `Checkbox`. The flat components, such as `DialogRoot`, are removed. The types have two names: `Dialog.Root.Props` and `DialogRootProps`. ([#704](https://github.com/vase-ui/vase-ui/pull/704))
- Element: the `#render` slot is the `element` slot. Its scope is `{ props, elementRef, state }`. Bind `v-bind="props"` and `:ref="elementRef"` on your element. ([#714](https://github.com/vase-ui/vase-ui/pull/714))
- `as` takes a tag or a component on each part that renders an element, and the `element` slot wins over it. A native form control, a form element, a native label and an image have no `as`, such as `Input`, `Checkbox`, `Fieldset.Root`, `Field.Label` and `Avatar.Image`. A part that renders another part or no element also has no `as`. ([#714](https://github.com/vase-ui/vase-ui/pull/714))
- A template ref of a part has `element`, the native element of the part. ([#714](https://github.com/vase-ui/vase-ui/pull/714))
- `nativeButton` and `nativeLabel` are removed. A part reads its element. An element that is not a native button gets `role="button"`, a tab stop, and a click from Enter and Space. ([#699](https://github.com/vase-ui/vase-ui/pull/699))
- `stateClass` and `stateStyle` are removed. Bind `class` and `style`, or select the state in CSS. ([#662](https://github.com/vase-ui/vase-ui/pull/662))
- The constants of attribute names, `*DataAttributes` and `*CssVariables`, are removed. Write each name as text. The page of each component lists its attributes and CSS variables.
- A data attribute is removed where CSS or ARIA gives the same state on the same element. Use the selector in its place:

  | Removed                                                           | Selector                                                                                                   |
  | ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
  | `data-disabled`                                                   | `:disabled`, or `[aria-disabled="true"]` on an element that is not a form control                          |
  | `data-popup-open`, `data-panel-open`                              | `[aria-expanded="true"]`                                                                                   |
  | `data-selected`, `data-pressed`, `data-checked`, `data-unchecked` | `[aria-selected="true"]`, `[aria-pressed="true"]`, `:checked`, `:not(:checked)`                            |
  | `data-readonly`, `data-required`, `data-invalid`                  | `:read-only` or `[aria-readonly="true"]`, `:required` or `[aria-required="true"]`, `[aria-invalid="true"]` |
  | `data-orientation`                                                | `[aria-orientation]`                                                                                       |
  | `data-focused`                                                    | `:focus`, `:focus-visible` or `:focus-within`                                                              |

- The `focused` state is removed. Use `:focus-visible` and `:focus-within`. ([#694](https://github.com/vase-ui/vase-ui/pull/694))
- Animation: `data-starting-style`, `data-ending-style`, the `transitionStatus` state, `openChangeComplete`, the `unmount` action and `preventUnmountOnClose()` are removed. Put the part in a `<Transition>`, and use its classes and hooks. ([#733](https://github.com/vase-ui/vase-ui/pull/733))
- A popup and a backdrop are in the DOM only while they are open or in their leave. `data-open` and `data-closed` of these parts are removed. A closed part with `keepMounted` has `hidden` and `inert`. ([#720](https://github.com/vase-ui/vase-ui/pull/720))
- `actionsRef` and each `Actions` type are removed. The template ref of a root has the methods, such as `close()` of a popup root and `validate()` of `Form` and `Field.Root`. ([#733](https://github.com/vase-ui/vase-ui/pull/733))
- `v-model` binds the value of each part. Replace `v-model:value`, `v-model:checked`, `v-model:pressed` and `v-model:layout` with `v-model`. In a render function, use `modelValue` and `update:modelValue`. The other models keep their names, such as `v-model:open`. ([#666](https://github.com/vase-ui/vase-ui/pull/666))
- A model that is not `undefined` is the value at each moment. While the model is `undefined`, the part owns the value, and it keeps its last value. A change between the two gives no warning. ([#664](https://github.com/vase-ui/vase-ui/pull/664))
- The details of a change have `reason`, `event`, `cancel()` and `isCanceled`. The open change of a popup root also has `allowPropagation()`, `isPropagationAllowed` and `trigger`. The value change of Combobox and Autocomplete also has `allowPropagation()` and `isPropagationAllowed`. The other details have none of these three members. ([#713](https://github.com/vase-ui/vase-ui/pull/713))
- `event.preventVaseUIHandler()` is removed. Call `details.cancel()` to stop a change. To stop a native event before the part gets it, call `event.stopPropagation()` in a capture listener on the part. ([#738](https://github.com/vase-ui/vase-ui/pull/738))
- An attribute with the value `undefined` removes the value that the part gives it, such as `:aria-labelledby="undefined"`. A blank value replaces the value of the part. ([#695](https://github.com/vase-ui/vase-ui/pull/695))
- A prop that HTML names has the name of HTML: `readonly`, `autocomplete`, `autofocus` and `inputmode` replace `readOnly`, `autoComplete`, `autoFocus` and `inputMode`. The state key `readOnly` is `readonly`. ([#694](https://github.com/vase-ui/vase-ui/pull/694))
- The props `minDate`, `maxDate`, `minTime` and `maxTime` are `min` and `max`. ([#719](https://github.com/vase-ui/vase-ui/pull/719))
- Locale: a part with no `locale` uses the locale of the nearest `LocaleProvider`, else `en-US`, on the server and in the browser. No part uses the locale of the browser. ([#707](https://github.com/vase-ui/vase-ui/pull/707))
- Text direction: a part reads the direction of its own element (`dir` or CSS `direction`). ([#738](https://github.com/vase-ui/vase-ui/pull/738))
- Native form reset: an uncontrolled control gets the `default*` value that it has at the reset. A controlled control gets its `v-model` value of the mount. The reset emits only the `update:*` events of the models, and no change event. ([#763](https://github.com/vase-ui/vase-ui/pull/763))
- OTP Field, Slider, Resizable, the date and time fields and the pickers have no change reason `none`. ([#701](https://github.com/vase-ui/vase-ui/pull/701), [#703](https://github.com/vase-ui/vase-ui/pull/703), [#712](https://github.com/vase-ui/vase-ui/pull/712), [#719](https://github.com/vase-ui/vase-ui/pull/719))
- In a `Field`, a control writes your `aria-describedby` ids first, then the ids of the field, each id one time. Give `null` to write no `aria-describedby`. ([#763](https://github.com/vase-ui/vase-ui/pull/763))
- Number Field, OTP Field, Combobox, Autocomplete, the date and time fields and `Toolbar.Input` take no text that the user typed before the hydration. They take no form state that the browser restores. ([#718](https://github.com/vase-ui/vase-ui/pull/718))
- A portal part renders no element, so it has no `as`. `container` is `to`: a CSS selector, an element or a shadow root. A `to` of `null` renders nothing. ([#687](https://github.com/vase-ui/vase-ui/pull/687))
- The handle of a popup has no `store`. ([#720](https://github.com/vase-ui/vase-ui/pull/720))
- In a `Viewport` of Popover, Preview Card and Tooltip, key the content by the `triggerId` of the slot in a `<Transition>`. `data-current` and `data-previous` are removed. ([#720](https://github.com/vase-ui/vase-ui/pull/720))

#### Entry points and types

- `@vase-ui/vue/direction-provider`: set `dir` on `<html>` or on an element around the parts. For a server render, give `Slider.Root` its own `dir`. In place of `useDirection()`, use `:dir(rtl)` in CSS or `getComputedStyle(element).direction` in a listener. ([#738](https://github.com/vase-ui/vase-ui/pull/738))
- `@vase-ui/vue/merge-props`: import `mergeProps` from `vue`. It joins `class`, merges `style` and calls each listener of the same name, in the order of the arguments. For `mergePropsN(sets)`, call `mergeProps(...sets)`. For `mergeClassNames(a, b)`, use `normalizeClass([a, b])` or `:class="[a, b]"`. `makeEventPreventable` has no other form: call `details.cancel()`. ([#745](https://github.com/vase-ui/vase-ui/pull/745))
- `@vase-ui/vue/use-render`: build a component with `useElement` of `@vase-ui/vue/use-element`, `mergeProps(own, useAttrs())` of Vue and an `element` slot. The template of the component holds the tag and the state attributes. ([#738](https://github.com/vase-ui/vase-ui/pull/738))
- `@vase-ui/vue/use-forward-props`: a wrapper declares only its own props. A wrapper that declares a Boolean prop or a model of the part gives it the default `undefined`. ([#738](https://github.com/vase-ui/vase-ui/pull/738))
- `@vase-ui/vue/unstable-use-media-query`: use `@media` in CSS, or `window.matchMedia()` with its `change` event in `onMounted`. ([#738](https://github.com/vase-ui/vase-ui/pull/738))
- `@vase-ui/vue/types` exports `ChangeEventDetails<Reason, E>`, `GenericEventDetails<Reason, E>` and `ElementSlotProps<State>`. `VaseUIChangeEventDetails` is `ChangeEventDetails`, and `VaseUIGenericEventDetails` is `GenericEventDetails`. `HTMLProps`, `ComponentRenderFn` and `VaseUIEvent` are removed. ([#738](https://github.com/vase-ui/vase-ui/pull/738))
- These types are removed, also in their namespace forms: `TextDirection`, `ForwardedProps`, `AutocompleteItemValue`, `AutocompleteRootSetupProps`, `FieldValidityData`, `FieldsetLegendState`, `FormState`, `FormSubmitEventDetails`, `FormSubmitEventReason`, `MenuParent`, the five state types of Meter, `ScrollAreaCornerState`, `Coords`, `HiddenState`, `OverflowEdges`, `Size`, `ResizablePanelSize`, `SliderValueProps` and `SliderRootChangeEventCustomProperties`. The value `toastRootStateAttributesMapping` is removed.
